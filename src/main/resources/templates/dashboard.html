Demo Sequence
1
Compose and Encrypt Payment
The server simulates a sender phone. It encrypts a payment instruction using hybrid RSA-OAEP + AES-256-GCM and injects the packet into the mesh at the sender's virtual device with a TTL of 5.
Use the Initiate Payment form on the Dashboard.
2
Run Gossip Round
Each device broadcasts held packets to all other in-range devices. TTL decrements per hop. After one round, all devices hold the packet. Run multiple rounds to reduce TTL further.
3
Bridge Nodes Upload to Backend
The bridge node (phone-bridge) simulates walking outside and gaining 4G connectivity. It POSTs all held packets to the backend simultaneously, exercising the concurrent idempotency gate.
4
Reset Mesh and Cache
Clears all held packets from virtual devices and resets the idempotency cache. Account balances are preserved.

Encryption Scheme
OUTER LAYER
RSA-2048 / OAEP-SHA256
Encrypts the per-packet AES session key. Only the server holds the private key. Intermediaries cannot read or tamper with the payload.
INNER LAYER
AES-256-GCM
Authenticated encryption. Any single-bit tampering with ciphertext causes decryption to throw. The 16-byte GCM tag serves as a tamper seal.
IDEMPOTENCY KEY
SHA-256(ciphertext)
Hashed before decryption. ConcurrentHashMap.putIfAbsent acts as a JVM-local Redis SETNX. DB unique index provides defense-in-depth fallback.
Wire format: [256B RSA-enc AES key][12B IV][AES ciphertext + 16B GCM tag]
